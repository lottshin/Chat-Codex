# 发布前真机回归清单

本清单用于版本发布前的真实渠道验收，重点覆盖文件发送、飞书云空间中转站、微信/飞书适配器和审批链路。修改这些能力时必须至少跑一遍相关小节，并把结果记录到发布记录或测试报告。

## 前置条件

- 本地服务通过 `npm run chat-codex` 启动。
- 飞书机器人 App ID / App Secret 可用，当前聊天已完成配对。
- 飞书中转站已配置，来源可以是 `FEISHU_DRIVE_FOLDER_TOKEN` 或聊天内完成过配置的文件夹链接。
- 桌面目录可写。
- 准备测试文件：一张小图片、一个小 PDF 或 PPTX、一个大于普通文件消息限制的文件。
- 飞书中转站内至少有 2 个普通文件，其中至少 1 个图片文件。

## 飞书中转站

- 发送“看看中转站里面有什么文件”，应直接列出前 20 项，不应交给 codex/claudecode。
- 发送“看看中转云盘里面有什么文件”，行为同上。
- 发送 `/files` 或 `/show files`，应能看到刚列出的飞书云盘项，序号和中转站列表顺序一致。
- 列表后发送“下载第 2 个到桌面”，应弹出确认卡，卡片文件名必须是列表第 2 项；确认后保存到桌面。
- 列表后发送“把第二个保存到桌面”，行为同上。
- 列表后发送“把云盘里的图片保存到桌面”，应匹配中转站图片并弹出确认卡，不应发送前文提到的本地图片。
- 列表后发送“把中转云盘里的 jpg 文件保存到桌面”，应匹配 jpg 文件并弹出确认卡。
- 先发送“我说的是那个 jpg 文件”，应回复保存意图提示；再发送“保存到桌面”，应沿用刚才选中的文件并弹出确认卡。
- 未列过中转站时发送“下载第二个到桌面”，不应猜测文件，应提示先查看或提供明确文件。
- 所有下载都必须先确认，不应自动保存。

## 飞书 Drive 文件链接

- 发送“下载到桌面 <飞书文件链接>”，应弹出确认卡；确认后文件保存到桌面。
- 飞书在线文档、表格等非普通文件链接，应提示当前不支持导出或下载，不应伪造本地文件。
- 发起人以外的用户点击确认，应被拒绝。
- 目标目录不存在或不可写时，应提示错误，不应静默失败。
- 同名文件已存在时，应追加序号保存，不应覆盖原文件。

## 本地文件发送

- 自然语言“把 D:\...\test.pptx 发给我”应触发文件发送审批或确认，不应泄漏 `BRIDGE_SEND_FILE:`。
- `/sendfile D:\...\test.pptx` 仍应可用。
- Codex/Claude Code 最终回复提到本地文件后，发送 `/files` 应显示该文件；再发送“发给我”应弹确认，不应启动新一轮后端任务。
- 微信/飞书上传附件保存成功后，发送 `/files` 应显示该聊天附件；明确说“把刚才的附件发给我”应走确认，不应自动发送。
- 发送图片、PDF、PPTX 等常见文件时，微信和飞书都应能收到对应文件或清晰的失败提示。
- 普通互联网链接、网页内容或“把网上这个发给我”不应误触发本地发文件。
- 大文件在飞书中应走 Drive 兜底或给出明确原因，不应只表现为发送失败。

## 微信渠道

- 图片发送仍应可用。
- 文件发送仍应可用。
- codex/claudecode 正在处理时，应保留“正在处理，可用 /status 查看状态、/stop 终止”的必要状态提示。
- 普通进度不应刷屏，长输出应摘要化或限流。

## 发布前确认

- 函数契约：本次如果只改文档，确认无代码路径变化；如果改了实现，检查空输入、无权限、目录不存在、同名文件和非普通文件链接。
- 命名一致性：新增配置名、状态名、文案关键词需要全项目 grep。
- 错误码/状态码：新增错误原因需要同步文档和常量。
- 文档同步：新增聊天命令、配置项或输出格式必须同步 README 和相关设计文档。
- 版本号：新功能升 minor，bug fix 升 patch；纯文档清单不需要升版本。
- 多环境测试：至少覆盖飞书、微信；涉及 Windows 路径时必须在 Windows 上验收。
